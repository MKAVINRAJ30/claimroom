# ⚡ ClaimRoom

> **A real-time "first to claim" live sales room for small sellers.**  
> Built for **Build Something Real: The Serverpod Hackathon** using Serverpod 4, PostgreSQL, and Flutter.

---

## 🎯 The Problem

Small independent sellers in India and worldwide sell through **Instagram Lives** and **WhatsApp groups**. During live drop sales:
- Buyers comment `"mine"`, `"sold"`, or `"claim"`.
- The seller tries to track claims manually on paper or in spreadsheets while livestreaming.
- **Race conditions**: Multiple buyers claim the same unique item at the same time, leading to double-sales, lost orders, and angry buyer DMs.
- **Unpaid / ghost claims**: Buyers claim items but disappear without paying, leaving inventory blocked while other buyers were waiting.

---

## 💡 The Solution

**ClaimRoom** replaces spreadsheets and chat chaos with a dedicated, lightweight real-time sales room:
1. **Seller** creates a live room, adds products, and shares the 5-character join code (e.g. `K9X2P`) or direct link (`/?code=K9X2P`).
2. **Buyers** join live, watch products update instantly, and tap **CLAIM NOW**.
3. **Atomic Double-Claim Prevention**: Serverpod handles each claim inside a PostgreSQL database transaction with `LockMode.forUpdate`. Even if 50 buyers tap at the exact same millisecond, row-level database locking guarantees **exactly one claim succeeds**. Double-selling is mathematically impossible.
4. **Hold Timer & Auto-Release**: Winning claims get a **60-second hold**. If the buyer doesn't confirm in time, a Serverpod **Future Call** automatically releases the item back to the room. Expired holds can also be immediately claimed by any buyer.
5. **Real-Time Streaming**: Serverpod streaming endpoints push live events (`item_claimed`, `item_confirmed`, `item_released`, `item_paid`, `sale_ended`) to all attendees simultaneously.
6. **Mark as Paid & Ghost Buyer Resolution**: Sellers can toggle paid status per item directly in the live order sheet, tracking paid vs unpaid totals in real time.
7. **Order Sheet & Multi-Format Export**: When the sale ends, the seller gets an aggregated order sheet grouped by buyer with 1-tap **Copy WhatsApp Summary** and **Copy as CSV** buttons!

---

## 🛠️ How Serverpod 4 is Used

| Feature | Implementation | Why It Matters |
|---|---|---|
| **Database Transactions** | `session.db.transaction((t) => ...)` with `LockMode.forUpdate` | Guarantees atomic claims; prevents double-selling under high concurrency |
| **Future Calls** | `HoldExpiryFutureCall` via `session.serverpod.futureCalls.callWithDelay(...)` | Server-side scheduled task that automatically expires abandoned holds after 60s |
| **Streaming Endpoints** | `client.room.streamRoom(roomId)` via `session.messages.createStream(...)` | Real-time WebSocket event bus pushing instant state updates to all buyers & seller |
| **Shared Client** | `claimroom_client` generated by Serverpod | Type-safe shared models and endpoints between backend and Flutter frontend |
| **Embedded Database** | Serverpod embedded PostgreSQL (`config/development.yaml` & `config/test.yaml`) | Instant setup without requiring Docker or manual database configuration |
| **Protected Endpoints** | `sellerKey` validation on mutation & order endpoints | Prevents unauthorized buyers from tampering with inventory or accessing order data |

## 🚀 Getting Started

### Prerequisites
- [Flutter SDK](https://flutter.dev) (v3.44+)
- [Dart SDK](https://dart.dev) (v3.12.2+)
- [Serverpod CLI](https://serverpod.dev) (`dart pub global activate serverpod_cli` or `dart install serverpod_cli`)

### Running the App

1. **Clone the repository:**
   ```bash
   git clone https://github.com/MKAVINRAJ30/claimroom.git
   cd claimroom
   ```

2. **Start the Serverpod Server & Web App:**
   ```bash
   serverpod start
   ```
   *This boots the Serverpod API server (port 8080), Insights server (port 8081), applies database migrations to the embedded PostgreSQL instance, and launches the Flutter application in Chrome.*

3. **Running the Flutter App Separately (Desktop/Mobile/Web):**
   ```bash
   cd claimroom_flutter
   flutter run -d chrome
   ```
   *For cloud deployments, pass `--dart-define=SERVER_URL=https://api.your-project.serverpod.cloud/` or configure `assets/config.json`.*

ClaimRoom includes an end-to-end integration test suite that verifies atomic concurrency, double-claim prevention, hold timers, and order sheet aggregation against Serverpod's real embedded PostgreSQL test database:

```bash
cd claimroom_server
dart test
```

### Integration Test Suite:
- `full seller and buyer claim flow with sellerKey, atomic double-claim prevention, mark paid, and end sale`
- `20 parallel claims on one item (exactly 1 succeeds)`
- `Confirm after hold expired (fails)`
- `Claim on closed room (fails)`
- `Claim after hold expired without future call (succeeds)`
- `deleteItem on held item (fails)`
- `Wrong sellerKey on seller-only endpoints (fails)`
- `Claim limit: 4th held item for same buyer fails`

## 📱 How to Demo the Flow (2-Minute Demo Script)

1. **Launch the App**:
   - Open two browser windows side by side (Window A = Seller, Window B = Buyer).
2. **Start a Live Sale**:
   - In Window A, click **"⚡ Quick Start Instant Demo"** or create a room ("Friday Thrift Drop").
   - Click **"Open as Seller"**. Notice the 5-character room code (e.g. `K9X2P`) and your **Seller Secret Key**.
3. **Shareable Join Link**:
   - Click **"Copy Join Link"** on the seller dashboard. Open that URL in Window B; notice the join code is pre-filled automatically!
4. **Join as Buyer**:
   - In Window B, join as `"Priya"`.
5. **Demonstrate Atomic Claim**:
   - Tap **"CLAIM NOW"** on an available item.
   - Notice the instant real-time update in both windows:
     - Seller sees: `HELD BY PRIYA` with live countdown timer!
     - Buyer sees: `HELD FOR YOU (0:59)` with "CONFIRM CLAIM" and "RELEASE" buttons!
     - Timer turns red when under 10 seconds.
6. **Confirm Claim**:
   - Click **"CONFIRM CLAIM"**. Status instantly shifts to **SOLD**.
7. **End Sale & Order Sheet**:
   - In Window A, tap **"End Live Sale"**. Holds are released and the room navigates to the order sheet.
   - In Window B, the buyer sees a **"Sale Ended"** summary card listing their confirmed purchases!
   - In Window A, toggle **PAID** on the buyer's item.
   - Click **"Copy as CSV"** or **"Copy WhatsApp Summary"**!

## ⚠️ Known Limitations & Scope Boundaries

In accordance with hackathon guidelines, scope was kept focused on the core live sale problem:
- **Typed Buyer Names**: To keep barrier-to-entry zero for live stream viewers, buyers identify by typed name and optional contact rather than creating full auth accounts.
- **Seller Key In-Memory Protection**: Sellers receive a 16-character secret key on room creation, avoiding login friction while securing administrative actions.
- **Out of Scope by Design**: Payment gateway integrations, parcel delivery tracking, ratings, and real-time chat were deliberately omitted to prioritize atomic transactions, hold expiry future calls, and order sheet accuracy.
